# plan

Стратегия и очерёдность работ по этапам для старта с нуля и для действующего сайта. Аудит не проводит: факты берёт из audit.md или входа.

## Вход

- Цель (лиды, продажи, узнаваемость, точность ответов о бренде), бренд или проект, рынок и язык.
- Ограничения: команда, бюджет, сроки, стек, доступы.
- По возможности: данные спроса, результаты аудита, конкуренты, текущий журнал видимости.
- Нет цели: уточни только её. Остальное помечай допущением.

## Процедура

1. **Ветка.**
   - Старт с нуля: все этапы по порядку, этап 6 начинается вместе с этапом 1 (база до изменений).
   - Действующий сайт: начни с фактов аудита. Этап, выход которого подтверждён доказательством, отметь выполненным. Без аудита запроси его или выполни audit.md в минимальном объёме для этапа 2.
2. **Профиль бизнеса.** Один или несколько; YMYL отдельно (см. audit.md, шаг 2). Акценты:

   | Профиль | Акцент |
   |---|---|
   | SaaS / B2B | Открытые цены и документация; сравнения и альтернативы; обзорные площадки; роли в закупке и их возражения как основа портфеля запросов |
   | Ecommerce | Данные фида и карточек раньше текстов; категории; отзывы (ecommerce.md) |
   | Local | Профили, отзывы, согласованные данные; сайт как источник фактов (local.md) |
   | Издатель | Карта новостей, свежесть, авторы; собственные каналы аудитории |
   | YMYL | Эксперты с проверяемыми профилями, источники, собственные данные |
   | Неанглоязычный рынок | Портфель из запросов на языке рынка, а не перевод. Англоязычные версии страниц как средство роста цитирования — требует проверки (evidence.md) |

3. **Этапы.** У каждого: результат, условие перехода, владелец, зависимость, критерий завершения. Длительность этапов задаётся горизонтом (настройка, по умолчанию 90 дней) и ограничениями, а не фиксированными неделями.

   | Этап | Работа | Результат | Условие перехода |
   |---|---|---|---|
   | 1. Спрос | Поле и 1-3 ассоциации бренда «для кого и для чего». Для каждой темы две оценки: спрос в поиске и в промптах. Формулировки из CRM, проигранных сделок, поддержки, отзывов, форумов, подсказок поиска. Портфель запросов по visibility.md. Кто сейчас цитируется и рекомендуется — наблюдением | Карта тем с двумя оценками спроса, ассоциации, список наблюдённых конкурентов-источников | Темы связаны с тем, что продаётся; оценки спроса подтверждены данными или помечены гипотезой |
   | 2. Технический фундамент | technical.md для ключевых шаблонов: доступ целевых ботов, индексируемость, основной контент в raw или подтверждённый рендер, canonical, sitemap. Подключение доступных панелей (GSC, Bing Webmaster, Яндекс Вебмастер) | Список блокировщиков и их статус, подключённые источники данных | На ключевых URL нет подтверждённых непреднамеренных блокировщиков; оставшиеся unknown перечислены |
   | 3. Страницы и данные | Кластер от продаваемого: опорная страница и страницы по интенту и типу ответа. Карта «сущности × атрибуты × шаблоны запросов». Тест независимости для каждой новой страницы (refresh.md). Официальные факты (entity.md), фиды (ecommerce.md), профили (local.md) | Карта кластера, шаблон страницы, сверенные факты и данные | Каждая новая страница прошла тест независимости; факты сверены с официальным источником |
   | 4. Редакционный выпуск | Тексты по content.md с редакционной приёмкой. Неповторимые активы: собственные данные с методом, кейсы с исходной базой, опыт практики, инструмент. Программные страницы: сначала пилот на малой группе, масштаб только доказанного шаблона | Опубликованные страницы и минимум один неповторимый актив | Страницы прошли приёмку, индексируемость проверена по technical.md |
   | 5. Внешние подтверждения | offpage.md: карта независимых источников по запросам и поверхностям, план честной дистрибуции активов, работа с подтверждёнными возражениями | Карта источников и план размещений с владельцами | План привязан к наблюдённым источникам, а не к списку площадок по умолчанию |
   | 6. Замер и рефреш | База до изменений (measure.md, refresh.md), прогоны портфеля по visibility.md, повторный замер тем же портфелем в конце горизонта, рефреш по диагнозу | Отчёт с периодами, знаменателями и исключениями; список страниц на рефреш | Повторный замер сопоставим по контракту visibility.md; следующий цикл запланирован |

4. **Порядок.** Зависимости определяют очерёдность: подтверждённый технический блокировщик ключевых URL снимается до вложений в тексты этих URL. Этапы без зависимости идут параллельно. Универсальной последовательности нет.
5. **Роли.** Распредели задачи по командам: разработка (рендеринг, доступ ботов, разметка, скорость), контент и эксперты (тексты, данные, кейсы), PR и партнёрства (размещения, комментарии, исследования), поддержка и продажи (вопросы и возражения клиентов), продукт (справедливые возражения из ответов ассистентов). Общая цель и регулярная сверка. Собственный канал связи с аудиторией (рассылка, сообщество) снижает зависимость от выдачи.
6. **Ожидания.** Сроки появления первых ссылок и устойчивого сдвига, скорость оттока источников из ответов — требуют проверки (evidence.md), в план как обещание не входят. Целевые показатели — доли появлений и рекомендаций по стадиям портфеля и брендовый спрос, а не только переходы из ассистентов.
7. **Вне плана.** Покупка ссылок и упоминаний, массовая генерация без редактуры, сети сайтов, спам в сообществах, llms.txt как рычаг видимости (technical.md, evidence.md).

## Выход

- Документ: цель, профиль и YMYL, допущения, карта тем с двумя оценками спроса, один кластер в деталях, список активов, таблица этапов `этап | задача | владелец | зависимость | результат | критерий завершения | срок в горизонте`, метрики с источником данных, непроверенные области.
- Не возвращать: пороги и проценты из исходников как цели (доли категорий без владельца, число подзапросов, число материалов, число площадок, сроки цитирования), фиксированную сетку недель, устаревшие гейты отчётов платформ без сверки с platforms.md, обещания позиций или цитат.
