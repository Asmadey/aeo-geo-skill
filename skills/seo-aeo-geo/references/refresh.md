# refresh

Диагноз падения существующей страницы, правки по секциям, решение о слиянии или новой странице, чистка инвентаря.

## Вход

- URL, раздел или инвентарь страниц.
- Даты изменений страницы и сайта (релизы, миграции, правки шаблонов).
- Ряды по запросам и страницам из GSC или аналогичного источника (Bing Webmaster, Яндекс Вебмастер): клики, показы, CTR, средняя позиция, запросы. Источник данных и его ограничения — measure.md.
- По возможности: журнал видимости (visibility.md), логи, конверсии, входящие ссылки.

## Процедура

1. **Нет данных.** Верни пустую матрицу Keep/Fix/Remove/Add и пустую таблицу диагноза. Запроси выгрузку: URL, запрос, клики, показы, CTR, позиция, устройство, дата — за базовый и сравниваемый периоды. Демо-строки и примерные значения не заполняй.
2. **База до изменений.** Стартовый ориентир — 56 дней до изменения. Поправки:
   - сезонность: сравнивай с сопоставимым контрольным периодом (тот же сезон, та же длина);
   - размер данных: при малом числе показов окно расширяй, пока ряд не станет пригодным, и укажи это;
   - даты изменений: окно базы не пересекает правку, релиз или миграцию;
   - контрольный период фиксируй тем же способом, что и базовый.
   Зафиксируй текущие title, H1, URL, разметку, основные запросы с позицией и CTR. Без базы результат правки не оценивается: отметь это в выходе.
3. **Диагноз падения.** Четыре типа (evidence.md, S070):

   | Тип | Клики | Показы | Позиция | Действие |
   |---|---|---|---|---|
   | Потеря позиций | ↓ | ↓ | хуже | Обновление содержания, проверка каннибализации (шаг 6) и ссылок |
   | Перехват ответом в выдаче | ↓ | = или ↑ | = или лучше | Страницу не переписывать целиком. Дать причину перейти: данные, инструмент, детали, которых нет в ответе; извлекаемость по content.md |
   | Сдвиг намерения | ↓ | = | ≈ | Посмотреть текущую выдачу: сменился формат (видео, таблица, товарная страница) — перестроить формат |
   | Падение спроса | ↓ | ↓ | = или лучше | Не чинить: тему ищут реже. Проверить спрос по внешнему источнику |

   - Рост показов при падении CTR не приписывай AI-ответам, пока не проверены состав запросов, устройства, вид SERP и изменения сайта. Перехват по агрегату не доказывается.
   - Проверь внешние причины: сезон, обновление алгоритма, сбой отчётов, перенос трафика на другую страницу сайта.
   - Тип, не подтверждённый рядами, помечай гипотезой со следующей проверкой.
4. **Матрица секций.** Каждой секции страницы — одна метка:

   | Метка | Условие | Действие |
   |---|---|---|
   | Keep | Секция отвечает на целевые запросы, факты точны | Не трогать формулировки |
   | Fix | Мысль верна, исполнение устарело | Перепроверить числа, цены, даты, названия продуктов и версий по первоисточнику; сохранить автора, ссылку и методику исходного числа |
   | Remove | Неверно, устарело или дублирует | Удалить, проверить связность соседних блоков |
   | Add | Нет ответа на подзапрос, данных, сравнения | Самодостаточный блок по content.md; подзапрос из рядов запросов или портфеля visibility.md |

   - Кандидаты на усиление: запросы с показами, позицией за пределами первых мест и слабым CTR. Диапазон 5-20 из исходников — ориентир для отбора, а не порог.
   - Длина блока, доля вопросных заголовков и «текущий год» в тексте не являются требованиями (content.md).
5. **Правила правки.**
   - title, H1 и URL по умолчанию сохраняй. Изменение допустимо при подтверждённой причине (данные запросов или SERP), с контрольным замером и после подтверждения пользователя. Смена URL — по правилу подтверждения SKILL.md.
   - Разметку расширяй, а не заменяй. Требования к разметке — content.md.
   - Дату обновления меняй только при содержательной правке.
   - Подборки и рейтинги: тот же URL с новым содержанием, прошлые версии — на отдельный адрес (evidence.md, S086).
   - После публикации: sitemap, повторная проверка URL в доступной панели. Поддержку IndexNow поверхностью сверяй в platforms.md.
6. **Тест независимости.** Перед созданием новой страницы и перед слиянием двух:
   1. Разный ли интент у запросов? Сверь по наблюдаемой выдаче и формулировкам.
   2. Самодостаточна ли каждая страница: отвечает ли на свой интент без другой?
   3. Какие URL выдача показывает по общим запросам? Есть ли уже страница сайта с показами по кластеру?
   - Пересечение запросов и выдачи показывай числом (общих запросов, общих URL в топе) без ярлыков «высокое/низкое».
   - Пороги исходников (`report_generator.py`: >40% общих цитируемых промптов; `page_refresh_and_cannibalization.md`: 5+ общих URL выдачи — слияние, <3 — разные интенты, 3-4 не определено) триггерами слияния не являются. Нужен ли числовой порог, требует проверки на данных пользователя.
   - Решение: один интент и нет самодостаточности — расширять существующую страницу; разные интенты и самодостаточность — отдельная страница; иначе — блок в опорной странице.
7. **Чистка.**
   - Кандидаты: страницы без кликов и показов за согласованный период (в исходнике 12 месяцев — настройка), дубли по теме, устаревшие новости и акции.
   - Перед решением по каждой:

     | Вопрос | Если да |
     |---|---|
     | Есть ссылки, трафик из других каналов или конверсии? | Оставить или объединить |
     | Есть уникальный материал (интервью, данные, кейс)? | Переработать |
     | Стоит в плане контента? | Не удалять |
     | Есть близкая сильная страница? | Объединить и поставить 301 на неё, а не на раздел |

   - Типовые ошибки: не сняты показатели «после»; снятие с публикации дало 404 вместо редиректов; редиректы ведут на хабы вместо близких по смыслу страниц; шаблон продолжает создавать такие же слабые страницы.
   - Веди реестр редиректов.
   - Таблица `URL → решение → redirect` — предложение. Выполнение только для подтверждённого пользователем списка по правилу SKILL.md. Просьба «почисти каталог» подтверждением не является.
8. **Ритм обновления.** Универсального срока (месяц, квартал, полгода) нет. Срок задают изменение фактов (цены, версии, правила), спрос и риск ошибки: страницы с выручкой и YMYL проверяются раньше. Ранние сигналы: падение обращений при стабильном трафике, рост показов без кликов, потеря ссылок в журнале visibility.md. Тезис о доле недавно обновлённых страниц среди цитируемых требует проверки (evidence.md).

## Выход

- По странице: база (период, поправки), диагноз с числами и типом или «гипотеза + проверка», матрица секций, список правок, что не трогать, дата и способ контрольного замера.
- Для слияния или новой страницы: ответы теста независимости, числа пересечения, решение.
- Для чистки: таблица `URL | решение (оставить/переработать/объединить/удалить) | redirect | основание`, пометка «предложение, ждёт подтверждения списка».
- Не возвращать: демо-матрицу без данных, ярлыки каннибализации по порогам, вывод о перехвате AI по агрегату, смену slug или title без подтверждения, массовый noindex или удаление без согласованного списка, фиксированный календарь обновлений.
