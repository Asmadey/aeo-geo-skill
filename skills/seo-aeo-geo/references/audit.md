# audit

Комплексный аудит сайта и бренда: выборка, матрица проверок и покрытие, вызов применимых маршрутов, одна очередь работ. Владелец технической оценки 0-100 и контракта сопоставимости технических снимков.

## Вход

- Обязательно: URL или домен, цель пользователя.
- По возможности: рынок и язык, целевые поверхности, бренд и варианты имени, URL ключевых шаблонов, конкуренты, доступы (GSC, Bing Webmaster, Яндекс Вебмастер, аналитика, логи), предыдущий снимок для сравнения.
- Нет цели или рынка: выполни доступную часть, уточни только блокирующий факт (см. SKILL.md, «Маршрутизация»). Конкурентов и запросы, предложенные навыком, помечай как допущение.

## Процедура

1. **Рамка.** Зафиксируй цель, рынок, поверхности, доступы. Каждый недоступный источник данных сразу вносится в «Непроверенные области» с нужным доступом.
2. **Профиль бизнеса.** Выбери один или несколько профилей: SaaS/B2B, ecommerce, local, издатель, другой. YMYL (здоровье, финансы, право, безопасность) отмечай отдельно от профиля: он меняет требования к источникам, авторству и проверке фактов (см. content.md), а не тип бизнеса. Смешанный профиль не своди к одному ярлыку: стоматология с филиалами = local + YMYL, магазин с точками самовывоза = ecommerce + local. Local и ecommerce при совпадении вызываются оба. Весов по типу бизнеса нет.
3. **Выборка.** Бюджет, порядок распределения по шаблонам, стоп после трёх 429/5xx и повторный прогон того же списка заданы в SKILL.md, «Проверки и решения». Здесь не переопределяются. Сохрани список выбранных URL, число проверенных, исключённые с причиной («бюджет», «намеренно закрыт», «дубль»). Больший объём предложи на согласование. Аудит одной страницы ограничен ею.
4. **Матрица проверок.** Строки: URL выборки и проверки уровня сайта. Столбцы: области и `check_id`. Ячейка: `pass`, `fail`, `unknown`, `неприменима (причина)`, `не проверено (нужный доступ)`.

   | Область | Маршрут | Минимум |
   |---|---|---|
   | Доступ и индексация | technical.md | HTTP и редиректы, robots/WAF по целевому боту, noindex, canonical, sitemap, raw/render основного контента, внутренние ссылки, доступное подтверждение индексации |
   | Извлекаемость и контент | content.md | интент, title/H1, лид, ответные блоки, авторство и источники, видимая разметка |
   | Сущность | entity.md | распознавание по имени, официальные факты, согласованность профилей |
   | Внешний след | offpage.md | независимые источники по денежным запросам и поверхностям |
   | Видимость | visibility.md | портфель, протокол, журнал наблюдений |
   | Измерение | measure.md | что можно измерить при доступных выгрузках |
   | Свежесть | refresh.md | устаревшие факты, тип падения при наличии рядов |
   | Local / ecommerce | local.md, ecommerce.md | по профилю из шага 2 |

   Покрытие: по каждой области число проверенных объектов, `unknown` и причины. Отсутствие наблюдения не равно `pass` и не равно нулю.
5. **Вызов маршрутов по применимости.**
   - technical и content вызываются всегда, когда на входе URL.
   - entity: есть бренд или ответы ассистентов с фактами о нём.
   - offpage: задача про рекомендации или доверие, есть категория и рынок.
   - visibility: есть доступ к поверхности или пользователь дал ответы. Без доступа: протокол, портфель и пустой журнал, без цифр.
   - measure: есть выгрузки аналитики, поиска или логов.
   - local, ecommerce: по профилю.
   - refresh: есть ряды GSC или аналогичные и жалоба на падение.
   - Скрипты из `scripts/` запускай только для маршрутов с URL на входе и только после валидации версии (SKILL.md). Параллельный запуск не условие выполнения.
   - Непокрытую поверхность русского рынка (Яндекс, Вебмастер, Карты, Алиса/Нейро, GigaChat) веди по карточкам platforms.md со статусом «требует проверки»: ручной чек вместо вердикта.
6. **Устранение дублей.** Отделяй симптом от причины: «12 000 дублей URL» — наблюдение, находка — механизм, который их порождает (шаблон, параметр, фильтр). Одна первопричина = одна находка с одним владельцем-маршрутом, все доказательства из разных маршрутов собраны в её строку. Находка без доказательства в отчёт не попадает. Если действие неизвестно из-за стека, формулируй требуемый результат, а не способ реализации.
7. **Единая очередь.**
   - Приоритет: цель пользователя, масштаб, уверенность, зависимость задач (SKILL.md). Подтверждённая непреднамеренная блокировка релевантного доступа на ключевых URL идёт первой.
   - Проблема на странице с выручкой или ключевой для цели раньше той же проблемы на служебной странице (evidence.md, S097, S111).
   - Порядок задаётся причиной обнаруженного блокировщика и зависимостями, а не универсальной последовательностью «доступ → доверие → релевантность» (тезис S042 в evidence.md не служит универсальным правилом).
   - Изменения noindex, canonical, redirect, robots, удаления страниц — только предложение по правилу подтверждения SKILL.md.
   - Дорожная карта со сроками и этапами передаётся в plan.md. Аудит её не строит.
8. **Оценка 0-100.** Только по запросу пользователя и только по разделу «Техническая оценка» ниже. Без запроса оценку не выдавай.

## Техническая оценка

Ориентир только для заранее объявленного набора обязательных применимых проверок и при полном покрытии заявленной выборки. Состав, уровни и применимость заданы реестром `tech-v1` ниже. Реальная индексация и AI-видимость публикуются отдельно.

- До расчёта зафиксируй для поверхности целевой набор T: URL выборки, предназначенные для обнаружения и индексации. По умолчанию включай выбранные публичные URL. Подтверждённо намеренные исключения фиксируй с причиной. При спорном назначении URL итог предварительно не считай.
- Покажи размер исходной выборки, T, причины исключения и охват. Пустой T даёт «неприменимо» при действительном прогоне.
- Все числовые проверки выполняются на T. Наблюдения вне T сохраняются в отчёте.
- Индикаторы ошибок группируются по `check_id` и области. Проверку уровня сайта разворачивай в явно затронутые целевые URL: правило для корня само по себе не доказывает блокировку каждого пути.
- Оценка считается на одну заявленную поверхность. При нескольких поверхностях — отдельные оценки с их покрытием.
- Для постраничной проблемы доля = число уникальных затронутых URL / число уникальных применимых и проверенных URL для этого правила. Несколько наблюдений одной проблемы на URL считаются один раз.
- Неприменимые проверки исключаются с причиной.
- URL с финальным ответом не 2xx получает только `http_status` и `search_crawl_access` и исключается из знаменателей остальных постраничных проверок.
- Штраф по правилу = доля × вес уровня (10/5/2/1). Вычти сумму из 100, ограничь снизу нулём, округли до целого в конце.
- Недействительный прогон (типичному клиенту недоступно содержимое всех URL выборки, SKILL.md) или неполное обязательное покрытие: оценки нет.

**Потолки.** Знаменатель потолков — отдельно |T|. B — объединение URL из T с подтверждённым fail хотя бы по одной critical-проверке. Каждый URL в B учитывается один раз независимо от причины. Блокировка обхода, HTTP-ошибка и читаемый noindex на разных URL дают один общий потолок. Применяется самый строгий из сработавших:

| Условие при действительном прогоне и полном обязательном покрытии | Потолок |
|---|---|
| Непустой T и B = T | 0 |
| Главная входит в B или доля B / T ≥ 0,5 | 50 |
| Одна high-проверка подтверждённо нарушена на каждом URL непустого T | 70 |

В отчёте сначала блокировщики, число заблокированных в T и разбивка по причинам с пересечениями. Затем веса, версия правил, дата, выборка и покрытие. Потолки и веса — настройки методики. Пример: 19 намеренно исключённых URL и один целевой URL с читаемым noindex дают 0 для одного целевого URL из 20 проверенных. Доля 1/1 в знаменателе отдельно взятой проверки сама по себе потолок 0 не запускает.

**Сопоставимость технических снимков.**

- Для каждого снимка храни поверхность, версию правил, T, статусы каждой пары `check_id × URL` (pass, fail, unknown, неприменима с причиной), режим и охват опциональных проверок (глубина, начальный URL, полнота обхода внутренних ссылок).
- Числовую динамику считай только при действительных прогонах с полным обязательным покрытием, той же поверхностью и версией правил.
- Возьми пересечение целевых URL, пересчитай оба ориентира на нём с одинаковым набором проверок и одной методикой. Опциональную проверку включай только при одинаковом протоколе и полном покрытии в обоих снимках.
- Исключения и пересчитанные баллы показывай отдельно от полных снимков.
- Проверки уровня сайта сравнивай только при той же границе обследованного сайта и протоколе.
- Разница применимости обязательных проверок допустима только при подтверждённом изменении причинной проверки: например, исчезновение 404 открывает проверку контента. Если первое состояние или изменение применимости вызвано нехваткой данных либо сменой протокола, числовой динамики нет.
- Пустое пересечение: выводи срезы без динамики. Изменение состава цели фиксируй отдельно.

**Реестр `tech-v1`.** Уровни и веса взяты из `SEVERITY_WEIGHT` в `geo_audit.py` (critical 10, high 5, medium 2, low 1). Назначение уровней конкретным проверкам — проектное решение этой версии, а не рыночный норматив. Обязательные проверки нужны для оценки: если обязательная применимая проверка не выполнена хотя бы на одном URL из T или в обязательной проверке уровня сайта, покрытие неполное и оценки нет. Опциональная проверка входит в сумму только при полном покрытии, отчёт перечисляет вошедшие. Как выполнять каждую проверку — technical.md.

| check_id | Исходная проверка | Уровень, вес | Область | Статус | Применимость и исключения |
|---|---|---|---|---|---|
| `http_status` | `http` в geo_audit, редиректы из check_access | critical, 10 | URL | обязательная | Финальный ответ **для типичного клиента** не 2xx после допустимых редиректов. Применима к URL из выборки. Ответ для диагностического UA бота сюда не входит. Расхождение (например, 200 для клиента и 403 для поискового UA) — отдельная находка technical «требует проверки по логам» без балла: подстановка UA не доказывает, как сервер обходится с настоящим ботом. Исключение: URL, который владелец назвал удалённым намеренно. Сетевой сбой даёт unknown, а не ошибку. |
| `search_crawl_access` | `robots_ai` и подтверждённая блокировка на стороне сервера | critical, 10 | URL; сайт при запрете корня | обязательная | Fail при применимом запрете обхода в robots или подтверждённом непреднамеренном отказе подлинному целевому поисковому боту. Для отказа нужны верификация бота по политике вендора и актуальные журналы WAF/сервера с датой, URL и решением о блокировке, либо эквивалентный авторизованный диагностический отчёт платформы. URL считается один раз даже при двух причинах. Training и пользовательские агенты вне числовой оценки поиска. Подтверждённый намеренный запрет отмечай отдельно и исключай из штрафов. При недоступной политике robots — unknown, если блокировка не доказана иным способом. При известной разрешающей политике и отсутствии подтверждённого отказа штрафа нет. Фактический доступ без доказательства — «не проверено». Диагностическая UA-проба выводится отдельно по `http_status`. |
| `index_directive` | `noindex` + X-Robots-Tag | critical, 10 | URL | обязательная | Для пары URL и поверхности фиксируй отдельно: наличие применимого noindex в заголовке/HTML, возможность его прочитать, фактическую индексацию. Бот может прочитать представление: noindex на URL для индексации — fail, читаемое представление без директивы — pass. Robots или подтверждённый серверный отказ блокирует получение представления: чтение «заблокировано», применение noindex «не подтверждено», проверка исключается из оценки как неприменимая, блокировка учитывается в `search_crawl_access`. При разрешающем robots, доступном представлении и отсутствии подтверждённых различий директиву можно оценить по ответу обычному клиенту с пометкой «представление — допущение». Одиночный 403 при подстановке UA этого не меняет. Известны разные представления, а ответ для целевой поверхности установить нельзя — unknown. Намеренно закрытый URL исключи из штрафа. Директива в ответе обычному клиенту сама по себе не подтверждает её обработку ботом или исчезновение URL из выдачи. |
| `canonical_target` | `canonical` после исправления Crawler 11 | high, 5 | URL | обязательная | canonical после разрешения от финального URL указывает на другой адрес без подтверждённого дубля или пагинации. Осознанный cross-canonical исключается с причиной. |
| `main_content_raw` | `raw_text`, пересобранная | high, 5 | URL | обязательная | Основное содержимое отсутствует в raw HTML. Без рендера: присутствие в raw — pass, отсутствие — unknown и неполное покрытие. |
| `sitemap_discovery` | `sitemap`, `robots_sitemap` | medium, 2 | сайт | обязательная для аудита сайта | Ни один sitemap не найден в robots и известных путях при успешных запросах. Для аудита одной страницы неприменима. |
| `internal_reachability` | `orphans`, `internal_links` | medium, 2 | URL | опциональная | Применима только при полном фронтире заявленной глубины. Иначе неприменима с причиной «фронтир неполный». |

Проверка применения noindex по запросу «сработал ли noindex?» — technical.md.

**Пример.** Из пяти проверенных URL один (не главная) отдаёт 404, остальные проверки чистые. Штраф `http_status` = 10 × 1/5 = 2, потолки не сработали, ориентир 98.

В оценку не входят title, H1, answer_first, question_h2, alt, формат изображений, таблица, schema, meta description, lang, dateModified и размер страницы. Это эвристики content и technical: они выводятся находками без баллов, потому что их влияние на поверхности спорно (Plugin 6-8, RU F7, Crawler 21).

## Выход

- Формат аудита и строки находки — SKILL.md, Output: вывод, цель, выборка и охват, до 15 главных находок (остальное — приложением), очередь работ, непроверенные области. Отдельные результаты для органического поиска, извлекаемости ответа и генеративной видимости. Неизмеренная поверхность получает статус, а не число.
- Шапка: профиль бизнеса, отметка YMYL, список выборки с исключениями, матрица покрытия по областям.
- Раздел «Что говорят ассистенты» — только наблюдённые ответы с датой, поверхностью и режимом. Без доступа — протокол и пустой журнал по visibility.md.
- При запросе оценки: блокировщики, B/T с разбивкой причин, штрафы по `check_id` с долями и знаменателями, потолок, итог, версия `tech-v1`, дата, поверхность, покрытие. Для динамики — оба среза и пересчёт на пересечении.
- Не возвращать: баллы 0-4 по блокам, веса по типу бизнеса, буквенные оценки и шкалы-вердикты («сильная база», «AI не видит бренд»), оценку без запроса, оценку при недействительном прогоне или неполном обязательном покрытии, оценку как прогноз видимости, план на 90 дней (это plan.md), выдуманные индексацию, ответы ассистентов или проценты видимости.
