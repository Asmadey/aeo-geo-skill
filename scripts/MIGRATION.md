## Фикстуры перехода с check_access.py

Новая схема содержит `schema_version` и записи по паре URL и агент с независимыми полями `robots_policy` (allow/block/unknown), `probe_http_status` (код или null), `verified_access` (allowed/blocked/unknown) и доказательством. Сверяй сохранённый старый JSON по смыслу через явное отображение полей, а новый по схеме и ожидаемым исходам:

| Фикстура | Старое наблюдение | Ожидаемое новое наблюдение |
|---|---|---|
| Переданный локальный robots с `User-agent: *` и пустым `Disallow:`, `--no-fetch --json` | `bots[].robots_allowed=true` | Для соответствующей пары allow. Проба страницы отсутствует, verified_access=unknown. Проверить отсутствие HTTP-запросов |
| Группы из eval 1 | Сохранённый ответ парсера | Проверить каждую пару URL и агент по правилам группировки и wildcard, включая /private/ |
| Разрешающий robots, обычный клиент 200, диагностический UA 403 | `bots[].robots_allowed=true`, проба 403 и «Критично» для поискового UA | allow, код пробы 403, verified_access=unknown, отдельное «требует проверки по логам» без штрафа |
| Сетевая ошибка при получении robots, иных данных о политике нет | Возможен булев true из отсутствующего текста | unknown с причиной сетевой ошибки |

Обязательный допуск потребителя - чтение новой версии и правильное поведение на каждом из этих исходов, включая unknown и отсутствие пробы. Версионирование, детализация, unknown и изменение приоритета диагностического 403 входят в контракт миграции.

## Допуск импортированных наблюдений к измерению

Сохраняй исходный файл и строки неизменными. Храни ссылку на файл и идентификатор строки, допускай повторный импорт без дублей по идентификатору исходного файла и строки. Записи JSON при импорте получают `provenance=unverified`, `citation=unknown`, `mention=unknown`, `recommend_for=unknown`, `recommend_against=unknown`. Код `citation_tracker.py` (строки 59-89, 271-280, 331-337) сохраняет одну форму записи для явного, неявного и подставленного `both` и пишет `sample` туда же без признака источника. Поэтому карантин охватывает все статусы, включая `ghost` и `neither`. Сходство с демонстрационным текстом само по себе не классифицирует запись.

По сохранённому ответу, ссылкам/выдержке с метаданными или явному подтверждению владельца по конкретным строкам проверь происхождение, завершение прогона, условия и каждый заявленный исход. Подтверждённые демонстрационные строки получают `provenance=demo` и остаются вне метрик. Подтверждённые реальные строки получают `provenance=observed`. Заполняй только те флаги, которые подтверждены. Подтверждение происхождения без подтверждения результата сохраняет исход `unknown`. Для полноценного сравнения периодов дополнительно нужны сопоставимые ключи сравнения из visibility.md, включая назначение одиночного сценария либо восстановленный контекст многоходового. Относи строки без необходимых полей к архиву ограниченного охвата. Для старого CSV используй тот же допуск, если происхождение или условия не документированы. Отчёт сверяет входное число строк, числа реальных, демонстрационных и ожидающих проверки строк и показывает исключения из каждого знаменателя. До проверки исходную автоматизацию не переключай.
